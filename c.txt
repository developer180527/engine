addon: the key nobody guarded, and five defects the ledger had not caught up with
The ledger stopped at BUG-0031 while five commits of defect-finding landed on
top of it. Catching up turned up a fixed bug with no regression proof and two
live defects in the protocol header.

── THE ENTRY THAT HAD NO TEST ──────────────────────────────────────────────
BUG-0034 shipped its fix in 4a65297 with nothing pinning it: engine_cook_worker
sent ERROR through oneLine and OUTPUT straight through, and OUTPUT carries a
path the parent OPENS. A newline is legal in a POSIX filename and a sibling
texture's path comes from the asset's stem, so such an asset produced a body one
line longer than the writer counted, and the parent blamed this process's write
for what was a filename.

cook_result_frame.rs cooks a synthetic textured glTF under a newline-named path
through the real worker CLI and requires the result to PARSE and say fail.
Mutation: removing the carryable guard reproduces the original symptom exactly,
"incomplete: END claims 2 line(s), found 3".

The fixture needs an EXTERNAL image URI. A glTF with its texture embedded as a
data URI cooks fine and emits no sibling, so it never reaches the record that
carries a path, the difference between exercising the bug and cooking a
triangle. The clean-name control is load-bearing for the same reason: a worker
that had stopped emitting OUTPUT records entirely would pass the newline case
perfectly while shipping the missing-sibling bug by another route.

── TWO DEFECTS IN THE PROTOCOL ITSELF ──────────────────────────────────────
BUG-0035. recordExact checked the value with carryable and did not check the key
at all, so recordExact("MY KEY", "/tmp/x") emitted a record every reader re-cuts
as key MY, value "KEY /tmp/x". The quiet wrong answer recordExact was split out
of record to refuse, hiding inside recordExact.

carryable cannot just be applied to both halves: a value legitimately contains
spaces, it runs to end of line, which is what lets a path with a space survive
— so usableKey is a separate predicate rejecting <= 0x20. record mangles the
space to '_' instead of refusing, because it returns void and its contract is
that it always emits; silently dropping a warning is worse than an ugly key.

Not reachable today, every call site passes a literal. Pinned because "no caller
does that yet" is not a property of the function.

BUG-0036. The manifest example was column-aligned in a header whose stated
contract is that a third party can reimplement the format from its comments. A
writer built from the aligned version emits padded keys and every reader hands
back a value with leading blanks. The bytes were always right; the specification
of them was not. A spec cannot use whitespace decoratively.

── THE THREE ENTRIES FOR WORK ALREADY DONE ─────────────────────────────────
BUG-0032, the probe's forgeable stdout. Observed rather than asserted: probing
one noisy module prints three "module 0 ok" and three "probe done" on stdout,
while the result file holds one MODULE record.

BUG-0033, engine_build's twelve warnings at exit 0, with an HONEST LIMIT stated
in the entry: what is pinned is that the tool still declares RECORD WARNING and
that its exit codes are distinguishable. No test yet packages a deliberately
broken project and asserts a WARNING record appears; that needs a fixture with a
dangling mesh reference and belongs in package_closure_test.

Deliberately NOT recorded: the .gitignore trailing-comment entry from 90959e2.
It is a real mistake and there is no test that could fail without the fix, so an
entry would be a pinned-by field pointing at nothing.

── VERIFICATION ────────────────────────────────────────────────────────────
Mutations, all three caught: the cook worker's carryable guard; usableKey
relaxed from <= 0x20 to < 0x20; sanitiseKey's space handling removed. The value
side is pinned in the opposite direction too, carryable("/tmp/my dir/x") must
stay true, so a later "fix" refusing spaces outright fails as well.

ctest -L unit 58/58. Ledger 36 entries, every pinned-by resolving. Docs gate 72
docs, 0 errors.
