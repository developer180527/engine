
bug fixes: eleven defects in the LOD/decimation work, three memory-unsafe

MEMORY SAFETY
* Cooked v4's LOD section stored counts INDEPENDENTLY of payload bytes and
  validated neither, the only place in the format where the two can disagree,
  since everywhere else the bytes are derived from the count. AssetService feeds
  lvl.indexCount to bgfx as a draw range, so a level claiming a billion indices
  over twelve bytes was a GPU read off the end. Now count*stride == bytes exactly,
  and every level range is clamped to the level's own indices.
  The section also shipped UNFUZZED. The harness now generates v4/v5 levels and
  carries InflateLod* corruptions, needed, because the generic corruptions only
  damage header fields: deleting the validation left the explore lane GREEN until
  those existed. Four regression seeds.
* (int32_t)floor(NaN) in the cell index: INT_MIN on x86-64, 0 on arm64, making the
  cook architecture-dependent and breaking the determinism the DDC rests on.
* CellHash multiplied int32_t by 73856093, signed overflow at cell index 30, so
  every real mesh, and a UBSan trip on an ordinary asset.

LEAKS AND LIFETIME
* Palette slots leaked one 8 KB palette per animated entity per PLAY SESSION: the
  remove hook was registered on the editor world, and hooks are world state, so the
  snapshot world, where entities are actually created and destroyed, never had
  one. "Bounded" was wrong: bounded per session, unbounded across them. Installed
  per ticked world; skin_palette_test pins that flecs fires on_remove during world
  TEARDOWN, and asserts the hookless case leaks, so the pass means something.
  release() is idempotent too, a double release aliased one palette to two
  entities, presenting as an animation bug elsewhere.
* Eviction freed level 0 while counting the LEVELS' bytes as reclaimed, so the
  budget never came down and the buffers stayed for the process's life. Fixed with
  its other half: runtime_frame collected in-use handles from MeshRenderer only,
  never LodMesh, and freeing levels without that is a use-after-free.
* unloadMesh left the dedup cache pointing at a freed slot. Handle::valid() is just
  id != 0, so once anything reused the slot, loadMesh(samePath) returned A DIFFERENT
  MESH. Reachable from unloadScene and from Lua.

CORRECTNESS
* Every LOD level drew with material[0]: decimation dropped the submesh ranges, so
  a multi-material prop CHANGED COLOUR at its first threshold, 96 of the kit's 176
  meshes. Clustering stays global, the index rebuild is partitioned by group, and
  format v5 carries the table (v4 still loads: no table reads as one range, which
  is what v4 meant). Ranges tile from zero, so submeshesTile() holds and the shadow
  pass keeps R19's one-draw path. Cooker kVersion 15 -> 16.
* The triangle census overstated the saving: trisFull was banked before the
  sentinel-radius early return, trisDrawn only after it, so an item that kept full
  detail counted its triangles in the counterfactual and zero in the actual. A
  counter that exists to justify a feature must not be able to flatter it.
* scene_cooker held a FIFTH copy of the JSON UB core/json_read.h was written to
  remove, on the same hand-editable .scene, plus ~45 value() calls that throw on a
  wrong-typed key, and the only try/catch wrapped the parse, so "id": "3" escaped
  onto a cook thread.
* Dead unreachable branch in decimateToRatio.
