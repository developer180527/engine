render: decimation gives LOD something to select, 62.2% of triangles

R20 built LOD selection, mutation-tested it, and measured it at exactly zero
benefit. The reason was never selection: `MeshCooker` could not decimate, so a
"level" was another kit mesh with the same triangle count. Selection was correct
and had nothing to select. This is the missing half.

`decimate.{h,cpp}`, vertex clustering, chosen over quadric error metrics on
purpose: it cannot produce non-manifold output, it is O(n), and it is
deterministic, which the shared DDC requires. The cell representative is the
cell's first vertex in index order, never a centroid, so every attribute on a
surviving vertex belongs to a real one. Authors steer by triangle RATIO, because
grid resolution is absolute and the same value gives 96% reduction on a dense
mesh and 0% on a prop.

The cooker emits three levels (40/15/5%) for static meshes above 2 000
triangles, and ships a level only if it is 20% cheaper than its parent, a level
that is not meaningfully cheaper is worse than no level, which is the state R20
measured. `lodCount` did NOT go into `MeshHeader`: it is a fixed-size block and
`static_assert(sizeof(MeshHeader) == 80)` caught the growth, so the count leads
the LOD section instead.

Three bugs found wiring it up, all of the same shape, LOD looking inert at
scene scale for reasons that were not LOD:

  - `AssetService`'s mesh dedup cache returned on a HIT without handing back the
    chain, so exactly one entity per mesh got levels. 20 000 objects over 176
    meshes meant 176 LOD'd entities. The chain now lives in `MeshResidency`.
  - only `SceneService` set `LodMesh`; `entity_serializer` did not. The same
    asset rendered with LOD in the player and without it in the editor.
  - `gen_fuzz_scene.py` selected `ASSET_STATE_COOKED = 1`, which is `Registered`,
    not `Ready`. The 20 000-entity fuzz scene was drawing 2 objects. Every LOD
    measurement taken on it was taken on an empty scene.

And the census now counts TRIANGLES, not just entities per level. Entities per
level says LOD is running; triangles say whether it is worth running, which is
the question R20 could not answer. Measured on the fuzz scene: L0 475, L1 710,
L2 795, L3 541, 0 broken, 3 719 383 triangles submitted against 9 828 860 at full
detail, 62.2% saved.
