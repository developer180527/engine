runtime: fuzz SceneService itself, and src/runtime reaches hardened

The last change fuzzed both scene PARSERS and deliberately left `src/runtime` at
`working`, because nothing drove `SceneService`, the thing that consumes the
parse result. This is that target.

Real everything: a real AssetService over real registries, a real flecs world,
real cooked meshes on disk, and bgfx on the **Noop** backend so every handle
path runs without a GPU (the arrangement mesh_dedup_test already uses). The
scenes are hostile in the fields only a consumer interprets, duplicate and
zero entity ids, self-parents, dangling parents, 40-deep chains, out-of-range
string offsets, enum bytes far outside their ranges, and truncated files.

Four properties the parse fuzzer structurally cannot see, because they are the
consumer's own failures rather than the parser's:

  - a REJECTED load must leave nothing behind. Spawning half a scene and then
    returning 0 is a leak no parse test can detect.
  - load → unload must be exactly balanced against the world's entity count.
    That property is what makes level streaming possible at all.
  - parent links must terminate.
  - handle hygiene: an unissued or already-unloaded handle is false, never a
    crash, and sceneEntityCount must agree with what the world gained, unload
    destroys from that list, so a disagreement is a leak or a double-destroy.

6 000 explore cases pass clean. SceneService held up, and no bugs were found,
which is the honest result, not a disappointing one, but it does mean a passing
lane proves nothing by itself. So the properties are mutation-verified instead:
removing the `destruct()` in `unloadScene` reports "load/unload LEAKED", and
swapping `safeReparent` for a raw `child_of` aborts inside flecs' childof-depth
recursion. The second is recorded precisely in the corpus file, the cycle is
caught by flecs dying before the ancestor-walk assertion is reached, so the walk
only earns its place for a cycle flecs would tolerate.

The corpus is therefore documented as COVERAGE ANCHORS rather than bug repros:
seeds pinned for the paths the properties depend on, with the mutation commands
that prove they bite written next to them.

`src/runtime` -> `hardened`. `engine_fuzz_target` gained an optional LIB
argument for it; the byte-level targets stay on engine_core so the deserializers
remain linkable without the renderer.
