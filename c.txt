ci: make the Windows leg report a fixable list, and fix what it would hit

The Windows CI leg already existed (windows-msvc, experimental: true), this
makes it useful and removes the breakage I could find without a Windows box.

── the leg ─────────────────────────────────────────────────────────────────
The whole point of an experimental leg is to turn "broken on Windows" into a
specific, incrementally fixable list. That list was useless: reading it meant
downloading a 40 MB artifact and scrolling. The build output is now tee'd, and
a failing leg publishes DE-DUPLICATED compiler errors to the job summary, so
200 instantiations of one mistake read as one line. Handles both spellings,
MSVC's "error C2065:" and GCC/Clang's "error:", and says so explicitly when
nothing matched, because that means the failure was in CONFIGURE or LINK and
the summary cannot help.

Both branches of that shell were run locally against synthetic logs; the first
draft was wrong (the `||` fallback attached to `head`, which never fails, so it
could never have fired).

── breakage the leg would have hit ─────────────────────────────────────────
- title_bar_windows.cpp used SHAppBarMessage/APPBARDATA with no <shellapi.h>.
  A guaranteed MSVC error, in the file that leg exists to validate.
- asset_path.h and project_context.h include <windows.h> with no NOMINMAX,
  and they are HEADERS, so the min/max MACROS leak into every consumer TU and
  break std::min/std::max at some unrelated call site, as a template error
  naming neither. Both now define NOMINMAX and WIN32_LEAN_AND_MEAN first.

I also swept for unguarded POSIX includes and found none: every unistd.h,
dlfcn.h, pthread.h and sys/* include in engine code is already behind an
__APPLE__/__linux__ guard. My first check flagged engine_build.cpp and was
wrong, the pattern did not match the guard style. The tree is more
Windows-ready than the roadmap entry implies.

Not flipped off `experimental`, nothing has gone green yet, and that flag is
the ratchet for when it does.
