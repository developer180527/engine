ci: the gating leg on every push, the other five nightly

Wall clock was 11m27s, set ENTIRELY by Windows x64 at 11m22s, for a verdict
macOS had already delivered in 4m53s. The test lane inside that is 20 SECONDS;
the rest is getting to the point where you can test.

So the gating leg runs on every push and the other five run nightly at 02:00
UTC, plus on demand. ~11m27s -> ~6m50s.

── WHAT MADE THIS SAFE TO DO ───────────────────────────────────────────────
Both Windows legs flipped to experimental: false. They went green in
32999369599, and this file's own ladder rule is to flip on first green, "it is
a LADDER, not a resting place". That ordering matters: nightly AND non-fatal
would have been a very weak ratchet. All six legs are now hard failures.

── THE MECHANISM, AND THE ONE IT AVOIDS ────────────────────────────────────
GitHub does not expose `matrix` to a job-level `if`, so per-leg selection has to
happen BEFORE the matrix exists. A small `plan` job emits the matrix as JSON,
defined once and filtered by event rather than duplicated per event.

The tempting alternative, keep every leg and make its STEPS conditional,
burns a runner per leg and produces a green job that built nothing. That is
exactly BUG-0016, a lane reporting ok while exercising nothing, and this repo
has now shipped that shape twice. The plan job fails loudly on an empty
selection for the same reason.

── THE TRADE, STATED RATHER THAN DISCOVERED ────────────────────────────────
A portability regression can now sit on main for up to a day. Three things make
that acceptable, and all three are in the ledger's open list rather than only in
a commit message: every leg is a hard failure so the nightly still ratchets;
workflow_dispatch runs the full matrix before anything that matters; and the
bugs these legs catch, a missing <cstring>, an x86-64-only prebuilt DLL,
alignof(max_align_t) differing from __STDCPP_DEFAULT_NEW_ALIGNMENT__, arrive
with code, and code lands on a schedule of hours.

── TWO MEASUREMENTS WORTH KEEPING ──────────────────────────────────────────
The push path is now bounded by TSan (~6m50s), not macOS (~4m53s). The
sanitizers stay on it deliberately: BUG-0001, 0002 and 0003 all came from those
lanes, and moving them to save under two minutes would undercut the reason most
of this ledger exists. Recorded as the next candidate, with its cost named.

And the six-minute build is ~110 LINK steps at a 97% compiler-cache hit rate.
Compilation is already free; the time is ~85 test executables each statically
linking the whole engine, and sccache does not cache links. That is why the
first idea, trimming targets with ENGINE_BUILD_EDITOR=OFF / SAMPLES=OFF, was
measured and DROPPED: it skips 10 of 1756 actions and 4 of 116 links, while
costing two real build-time invariants (sample_minimal is the SDK-surface
honesty check, and imgui_bgfx.cpp / imgui_impl_glfw.cpp compile nowhere else).
Three link steps is not worth a coverage hole that nothing turns red for.

Docs gate clean. Suggested exclusion: c.txt is your scratch file.
