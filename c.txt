render: one shadow draw per caster, and submeshed casters instance

R18 left the shadow pass open. It had the same submeshes.empty() exclusion and its own
inner range loop, so a multi-material prop cost one shadow draw per material group and
could never instance.

IT DID NOT NEED R18'S TREATMENT, IT NEEDED LESS. A shadow draw binds NO material: the
program is fixed and depth-only, and the range loop existed purely to walk index ranges.
So if a mesh's ranges TILE its index buffer, drawing the whole buffer once renders
exactly the same triangles as drawing every range, one draw instead of N, and the mesh
becomes instanceable. No expansion, no extra sort, no extra pass.

                                  before                   after
  5 000 props, shadow draws       1 227                    175
  5 000 props, shadow instanced   76 submits / 386 items   169 / 884
  5 000 props, Render.shadow      0.566 ms                 0.186 ms
  50 000 props, shadow draws      322                      120
  20 000 cubes (control)          1                        1, unchanged

Whole render path at 5 000 real props is now 2.57 ms: extract 0.59, expand 0.44, cull
0.21, shadow 0.19, submit 1.10.

THE TILING ASSUMPTION IS CHECKED, NOT TRUSTED. Mesh::submeshesTile() verifies the ranges
are contiguous from zero, non-overlapping, and sum to indexCount. MeshCooker appends them
sequentially and accumulates the same counts into header.indexCount, so cooked meshes tile
by construction, but meshes also arrive through the source importers, and a future cooker
change must not silently break shadows. A mesh that fails the check falls back to
per-range draws and logs once through the Renderer tag. Across the kit's 176 cooked meshes
the warning fired ZERO times. Cost: O(submeshes), under two on average, and only for
casters that survive the light cull.

Side effect worth knowing: shadow draws count against the same kMaxDrawsPerFrame ceiling
as colour draws, so cutting 1 052 shadow draws at 5 000 props also buys the colour pass
that much more headroom.

NOT ADDRESSED, and it is the real remaining shadow limitation: ALPHA-TESTED CASTERS.
Collapsing ranges is only sound because the shadow program ignores materials entirely,
which also means foliage and fences cast solid rectangular shadows today. That predates
this change. Fixing it needs an alpha-test shadow variant selected per range, which is a
feature rather than a fix, and it would partly undo this collapse for the materials that
need it. Recorded in issues.md R19 and in a new Shadow pass section of render/info.md.
