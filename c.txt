render: route diagnostics through the logger, and log the silent failures

Every renderer printf bypassed core/logger.h, and Logger is not just stdout, it keeps
the ring buffer the EDITOR CONSOLE reads. So renderer diagnostics were invisible to
anyone not watching a terminal, including DRAW CEILING HIT, the one message that says
the frame on screen is missing geometry. It was on stderr.

CONVERTED. All printf/fprintf in src/render are gone (shader/ already used the logger),
with levels that carry information:

  LOG_ERROR    output is wrong or the device is gone, draw ceiling hit (frame
               INCOMPLETE), null native window handle, bgfx init failed
  LOG_WARN     degraded but still rendering, a material's shader missing from the
               cooked cache
  LOG_INFO/SUCCESS  one-time facts, scene framebuffer, shadow map size and cost,
               which standard program was selected

ADDED: two degradations that were completely silent and both change the shape of every
frame:

  * no BGFX_CAPS_INSTANCING: every batch run falls back to per-draw. On real content
    that is the difference between 299 draws and 41 571, and nothing said so.
  * instance data buffer exhausted mid-frame: that run and every later one submit
    per-draw, so the frame's draw count exceeds what batchRuns predicts. Previously a
    bare `continue`.

THE HARD RULE, now written into info.md: every renderer log site is latched or deduped.
These live in or beside the submit loop, and a diagnostic that fired per draw would cost
more than the thing it reports and bury the log it belongs in. Bools for the ceiling and
the two new warnings, std::set for missing shaders and data-driven binds. Add a log here
only with a latch.

diag/diag_report.h deliberately keeps printf: it renders multi-line REPORTS (submit
counters, VRAM census) on demand from tools, not events, and eleven lines per report in
the editor console is noise.

Verified the ceiling actually routes through the logger by reading render_pipeline_test's
output, that test trips the ceiling by design, rather than trusting the macro swap.

Re-verifying the docs caught THREE STALE CLAIMS left by my own earlier commits, all now
corrected: render/info.md still said submeshes fall through to per-draw (R18 changed
that), that R7's dedup buys nothing (R18 is exactly what made it work, 2 869 binds for
2 869 draws became 299 for 299), and that bone palettes are uploaded per submit inside
the submesh loop (R4 hoisted that to once per item, and it is why skinned items are the
one thing R18 does not expand). world/info.md now records that VisibleDraw carries a
submesh ordinal and why batchRunLength must compare it.
