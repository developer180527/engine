docs+fix: HEAD did not build, .gitignore silently ate src/tools/build/

Updating the docs turned up something worse than stale prose: the last three
commits are INCOMPLETE. src/tools/build/package_closure.{h,cpp} were never
committed, because .gitignore's `build/` is unanchored and matches at any depth.
`git add -A` skipped them without a word.

HEAD therefore does not build from a fresh clone. src/CMakeLists.txt lists
tools/build/package_closure.cpp and engine_build.cpp includes its header; both
are committed, the implementation is not. It compiles here only because the
files exist locally.

Anchoring the pattern is not an option, Kits/*/build and
fps_shooter/scripts/build genuinely rely on matching at depth. Naming source
`build/` fights too strong a convention anyway (IDE indexers, CI caches, docker
ignores all assume it is output), so the directory is now src/tools/packaging/,
which is also just a better name for what it holds.

THE SAME OVER-BROAD MATCH WAS IN engine_doctor. EXCLUDE_DIRS tested every path
component, so src/tools/build/info.md was invisible to the checker, a doc that
silently does not exist, which is the exact failure the tool exists to prevent.
Split into EXCLUDE_ROOTS (build outputs, matched at the repo root only) and
EXCLUDE_DIRS (things that nest by nature: .git, .cache, .kitbuild, node_modules,
third_party, vendored code lives under modules/ too). Doc count 59 -> 60.

Docs then updated for what actually shipped. Five claims had gone false, and the
doctor could not catch any of them: it compares `verified:` against the git
history of covered code, which says nothing about whether the PROSE is still
true. Worth knowing about the contract's reach.

                                     yet" was wrong, it runs in a shipped dist

  process/roadmap.md                 the packaging gate is resolved; R3 is half

New src/tools/packaging/info.md records the three packaging bugs and the rule
they produced, ship what the cooked asset REFERENCES, never what its filename
suggests, plus the honest note that the ordering assertions are vacuous on a
filesystem that returns sorted entries.
