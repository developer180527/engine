build: engine_build passed a bare -j — unlimited compilers, 24 GB, frozen machine

`cmake --build <ship-tree> --target engine_player -j` with no number means
UNLIMITED jobs to make. Packaging configures a fresh ship tree, so that target
compiles the whole engine (~1300 TUs: Assimp, bgfx, Jolt, ozz) and make
launched a compiler per ready target simultaneously. At ~0.5-2 GB per heavy C++
TU it exhausted 24 GB of RAM and froze the machine's UI outright. Both call
sites (player, and each kit) had it.

The cooker was given thermal citizenship precisely because this machine melted
once already — cores-2, memory-budget admission, background QoS. Packaging was
never held to the same rule.

jobFlag() now bounds by cores AND RAM, because cores alone would not have
helped here: memory was the binding constraint. Budgets 60% of physical RAM at
~2 GB per compile — the same fraction COOK_MEM_BUDGET_MB defaults to, and for
the same reason (the OS and editor are still running; budgeting 100% of RAM is
how a "safe" limit still swaps a machine to death).

  this Mac  (12c/24GB): -j 7   (cores allow 10, RAM allows 7)
  potato PC ( 4c/ 4GB): -j 1   (cores allow  2, RAM allows 1)

ENGINE_BUILD_JOBS overrides for build farms. The chosen value is printed every
run so the decision is never invisible again.
