render+cook: GpuResourceCache wiring, and 32 MB of cook-time texture duplication

Two halves, one of which did not do what was expected — recorded because the
negative result is what found the real bug.

WIRING: loadTextureFromCooked now goes through GpuResourceCache, keyed by
normalised cooked path, with the whole load as the factory so a hit skips the
file read as well as the upload. Previously that path had NO dedup at all.
Measured effect on fps_shooter: none — the scene loads textures through
resolveTextureGPU on the async worker, not this path.

The async sites are deliberately NOT wired. bgfx memory from copy() is freed
only when a create call consumes it, and at those sites the worker has already
allocated; a cache hit would leave it unconsumed. That is a leak, introduced
while building leak infrastructure. The fix belongs earlier — the worker should
stage each .ctex once per mesh — and is scoped as follow-up.

THE ACTUAL DUPLICATION was at cook time. The pistol's four sibling .ctex files
were two byte-identical pairs (t0==t2 at 10.7 MB, t1==t3 at 21.3 MB): its glTF
has several materials naming the same images, and the cooker re-encoded and
re-wrote each into its own slot. 32 MB duplicated on disk, in the DDC and in
VRAM, for a three-mesh scene against a 128 MB target.

Note the runtime cache could never fix this: the duplicates had DIFFERENT
filenames, so path identity cannot see them. MeshCooker now keys siblings by
content (BLAKE3 over encoded payload + the header fields that change
interpretation) and reuses the earlier file. Dedup state is thread_local and
cleared per cook() — sibling names carry the mesh's uuid stem, so a stale entry
would hand out another mesh's file, and the in-process fallback reuses threads.

MeshCooker kVersion 12 -> 13.

Measured: pistol siblings 4 -> 2 files, 64 MB -> 32 MB, zero duplicate content
hashes remaining. VRAM is still 76 MB because the cooked mesh now holds 4
material references to 2 files and the async path uploads each separately —
but they are now PATH-identical, which is what makes runtime dedup tractable.

Also noted, not fixed: .cache has no GC, so the version bump left orphaned
siblings behind and total cache size grew to 113 MB.
