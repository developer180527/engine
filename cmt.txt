render: diagnostics module — churn, budget, census (one concern per file)

Phase 2 of docs/renderer-audit-and-plan.md. src/render was the least verified
subsystem in the engine (prototype tier, no test that could fail) because
rendering needs a GPU. These modules are built so the parts worth testing
don't.
render_stats_channel.h was 151 lines doing sampling, judging, budgeting and
formatting. Split into src/render/diag/:
  frame_gpu_stats.{h,cpp}  sample bgfx counters + churn verdict (only file
                           touching bgfx; sampleExplicit() is the test seam)
  gpu_budget.{h,cpp}       target tiers, ceilings, PASS/OVER — pure policy
  resource_census.h        resident set, per-owner cost, duplicates, leaks
  diag_report.h            formatting, isolated so the logic has no I/O
render_stats_channel.h is now a 32-line profiler adapter.
engine_player gains --budget low|mid|high, exiting 4 when over, so it can gate
a packaging step or fail loudly on the low-spec machine itself.

TWO FINDINGS FROM ACTUALLY RUNNING IT:
- The test caught my own wrong expectation. The shipped 23 MB frame does NOT
  pass the low tier: 23 MB of render targets exceeds the 20 MB sub-ceiling
  even though total VRAM is 18% used. That is the budget working — sub-limits
  are what push a project to shadowResolution 1024 (11 MB, PASS) instead of
  letting one allocation eat the whole allowance. Test now documents it.
- A "known limitation" I had written into info.md was really a defect: draw
  calls were formatted as megabytes, rendering "13 / 500" as "0.0 / 0.0 MB".
  Added BudgetUnit; the line now reads correctly.

tests/render_diag_test.cpp: 26 assertions, headless — churn (steady /
per-frame / leak / occasional), budget verdicts incl. peak-not-final and
unknown-tier-is-strictest, census totals + owner ranking + duplicate
detection, and leak baseline compare naming and costing the offender.

src/render/diag registered as `working`; src/render itself stays prototype
(the pipeline is still untested).
