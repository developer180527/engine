render: GpuResourceCache — identity, refcounts and a byte budget for GPU data

Phase 1 of docs/renderer-audit-and-plan.md. Audit finding R1: GPU resources
have no identity, no refcount and no dedup — TextureRegistry::addTexture is a
slot allocator, so two materials naming the same image get two copies in VRAM,
and nothing can say when either is free.

Three consequences, all addressed:
  - Duplicates are prevented STRUCTURALLY: resources are keyed by content, so
    asking twice returns the same handle. Not a cleanup pass — a duplicate
    cannot be created.
  - Leaks become definable: "unused" means refs == 0, a fact rather than a
    guess, so a detector can assert on it.
  - The render tooling becomes a query over one table. The census, per-material
    profile and duplicate report were impossible before not because nobody
    wrote them, but because the data did not exist.

C++, not Rust, applying the rule set in modules/net: Rust pays where untrusted
data or complex ownership lives. This touches no untrusted bytes (keys are DDC
hashes), and putting it in Rust would SPLIT ownership across the FFI boundary —
Rust holding refcounts, C++ holding live bgfx handles — which is the exact bug
class the cache exists to remove.

Design: sits ON TOP of the existing registries (the factory does the real
create + insert on a miss), so the six addTexture sites migrate one at a time
and registry RAII is untouched. Payload-agnostic, so dedup/refcount/LRU/budget
logic is unit-testable with a fake handle and no GPU — src/render has no render
harness. refs == 0 means EVICTABLE, not dead: a cache, not a unique_ptr.

gpu_cache_test, 33 assertions. Verified it can fail: deleting the refs==0
filter in evictOverBudget reports "referenced resource survives eviction
(freed 5000)". Restored byte-identical. Also fixed dedupSavedBytes(), which was
documented but never incremented and would have reported 0 forever.

src/render stays `prototype`: this component is tested but not yet wired into
any render path, and the pipeline remains untested.
24/24 unit, 2/2 docs.
