build: test the packaging path, it shipped an untextured game silently

The bug fixed in the previous commit had no test, and couldn't have one: the
logic lived inline in engine_build's main flow, reachable only by running a full
project build. That is why a filename heuristic survived long enough to ship a
game with every mesh present and every surface untextured.

Extracts it as pkg::meshClosure(), "given a cooked mesh, name every file the
runtime will look for", and tests it.

The central case is deliberately the one the old code got wrong: a cooked mesh
whose texture references share NO filename prefix with it. That is not exotic,
it is what a clean rebuild against a warm shared DDC produces, because the
manifest restores siblings under the names they were FIRST written with while
the mesh output takes the current uuid.

Also covered: a missing texture is NAMED rather than silently dropped (an absent
texture means the shipped game renders untextured, so the build must look
suspect); a texture shared by two meshes isn't double-counted, which is the
normal case given the cooker's content dedup; one texture in both slots of one
material is listed once; a corrupt or absent mesh is `unreadable` rather than an
empty success, shipping it as if it were fine loads nothing at that entity; and
a path-shaped reference is reduced to its filename, because a cooked blob can
arrive from a shared DDC, i.e. from another machine.

MUTATION-PROVED: reinstating the "<meshUuid>_t*.ctex" prefix scan fails 6 of the
assertions, the headline one included. Restoring passes.

Two things the synthetic fixture had to get right, both worth knowing: the mesh
reader derives section offsets from the header's counts (writing geometry bytes
without setting them puts the material section at the wrong offset), and
saveMesh does not derive materialCount from the vector. The fixture goes through
the real saveMesh/loadMesh rather than mocking, so it exercises the same reader
the packager uses.

Verified: full build clean, ctest unit 30/30 (was 29), engine_doctor 59 docs /
0 errors, and a real engine_build of fps_shooter still produces an identical
53.7 MB dist (3 scene mesh refs, 8 mesh files, 1 cooked shader).
