ci: stop cancelling main runs; don't build 4 platforms for a Markdown edit

Two independent causes of the cancelled-run noise:

- `cancel-in-progress: true` applied to pushes on main. Because work lands as
  a short series of direct commits, each push cancelled the previous in-flight
  run, so every commit but the last ended with no verdict at all. Now scoped
  to pull requests, where a superseded run genuinely is stale. Main is the
  ratchet: every commit on it gets a full result.
- Doc-only commits triggered the whole matrix — Assimp and bgfx compiled from
  source on four platforms to validate Markdown. Today's documentation work
  alone would have burned hours of runner time.

ci.yml now ignores '**.md' and 'docs/**'; a new docs.yml runs the same
engine_doctor contract in ~15s (pure Python, no CMake, no submodules, but full
history since staleness needs git dates). A commit touching code AND docs still
takes the full path, so the `docs` ctest lane still catches staleness whenever
code actually moves — the only case that can cause it.
