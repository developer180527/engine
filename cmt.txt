cook: engine default assets are a second asset root

Wiring ForwardPipeline to cooked shaders was blocked on a question I'd deferred
twice: where do the engine's OWN cooked default assets live, and how does
engine_build package them? The engine's shaders sit in /shaders, but cooked
assets live in a PROJECT's .cache.

The cheap answer turns out to be the right one: make the engine's shader
directory a second asset root. CookService scans it alongside the project's
assets, so standard.shader cooks into each project's .cache like any other
asset. That means:

  - no new packaging concept, engine_build already ships .cache
  - the duplication is free, every project cooks byte-identical sources to the
    same DDC key, so it is cooked once per MACHINE, not once per project
  - a project can override an engine default by shipping its own
  - ShaderLibrary needs no special resolution: one lookup path

Engine assets are ALWAYS IN SCOPE, including under SceneClosure. No scene
references a .shader, so a scoped cook would otherwise produce no programs and
the game would boot to a black screen, precisely the silent failure the shader
asset work exists to make loud.

Their sourcePath comes out relative and escaping ("../shaders/standard.shader").
That is fine and deliberate: registry.db lives in .cache, is machine-local, and
is rebuilt by a re-scan. Cooked output is keyed by UUID, so nothing downstream
cares.

Resolution order: setEngineAssetsRoot(), else $ENGINE_ASSETS, else the
build-time ENGINE_DEFAULT_ASSETS_DIR. Absent is normal and silent, a shipped
dist has no engine source tree and needs none.

Also renames docs/process/info_strcuture.md -> info-structure.md, and re-verifies
three info.md files that the doc contract flagged stale purely because the docs
reorg touched comments in files they cover (no behaviour changed).

Verified: fps_shooter's DEFAULT scene-scoped cook now reports "13 asset(s) in
closure (+10 engine default(s))" and produces a real .cshader (magic CSHD, v1,
30553 bytes) in fps_shooter/.cache/shaders. Idempotent on rerun. Wiping .cache
entirely and re-cooking serves all 4 assets from the DDC in 105 ms. Full build
clean, ctest unit 29/29, engine_doctor 59 docs / 0 errors.
