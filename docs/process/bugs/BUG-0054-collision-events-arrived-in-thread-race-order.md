## BUG-0054 — collision events reached scripts in thread-race order
- found:     2026-09-08
- status:    fixed
- class:     threading
- where:     src/plugins/jolt_plugin.h
- symptom:   two runs of the same scene from the same starting state produced different `CollisionEvents::entered` / `::exited` orderings, so gameplay callbacks fired in a different sequence each run. Nothing crashed and nothing logged — the physics looked right, and only the order in which a script was told about its contacts differed, which is invisible until something depends on it (first hit wins, damage application order, a kill credited to the wrong source).
- cause:     `OnContactAdded` / `OnContactRemoved` run on Jolt's worker threads and push into `m_pendingCollisions` under a mutex, so the vector's order is pure thread-arrival. `flushCollisionEvents` consumed it as-is and built an `std::unordered_map` whose iteration then drove the deferred `set<CollisionEvents>` calls — so a hash-table walk decided the order of structural ECS changes as well. `m_entityToBody`, `m_characters` and `m_charState` had the same problem one level up: they are walked to DESTROY bodies and to STEP characters, not merely looked up, and Jolt's own `Architecture.md` requires bodies to be added and removed in the same order for determinism because BodyID recycling feeds its contact sort.
- pinned-by: tests/determinism_gate_test.cpp
- lane:      unit
- proof:     `local` is sorted at the source on a total key — the pair normalised as (min, max) so a contact reported (a,b) in one run and (b,a) in another lands in the same place, then the enter flag, then the raw first id. `evMap` and the three entity-keyed maps became `std::map`. The determinism gate's `physics` tier now matches across 240 ticks on both A/A' and A/B, verified over 10 consecutive runs, and both pairs moved into the gating lane. Mutation: removing the sort alone turns both physics pairs red with an UNEXPECTED divergence and exit 1.
- note:      SORTED AT THE SOURCE, NOT IN THE HASHER, and that was a deliberate choice against one reviewer's advice. A digest that defensively sorted `CollisionEvents` before hashing would have shown the gate green while gameplay still observed the race — the instrument would have been lying about the exact defect it exists to find. The engine's own contract is that the vector order is what scripts iterate, so the order is what had to be fixed. The `std::map` swap costs an RB-tree walk per tick over tens to hundreds of entries, which is not measurable against `CharacterVirtual::ExtendedUpdate`; if it ever is, the answer is a hash map for lookup plus a sorted vector for iteration, with a measurement.
