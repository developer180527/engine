## BUG-0062 — Snapshot Play aborted on its first tick in any scene with a skinned entity
- found:     2026-09-13
- status:    fixed
- class:     logic
- where:     src/systems/animator_system.h, src/runtime/runtime_sim.cpp
- symptom:   a debug build aborts on the first fixed step of Snapshot Play with `fatal: type_info.c: 442: assert(ecs_id_in_use(world, component) == false): SkinnedMesh (ALREADY_IN_USE)`, whenever the scene contains an entity with a SkinnedMesh — which is every animated character. InPlace Play is unaffected.
- cause:     the animator's palette-release hook, an `on_remove` on SkinnedMesh, is per-world state, and for the play world it was installed LAZILY: `AnimatorSystem::run()` set it the first time it saw a world, which for the Snapshot world is the first fixed step. By then `startSimulation` has already called `SceneSerializer::loadIntoWorld`, and `loadSkinnedMesh` sets SkinnedMesh on every skinned entity (Memory mode carries the live skeleton handle). flecs refuses to set a hook on a component already in use, and the refusal is an assert. InPlace Play never calls `run()` — it animates the init world, whose hook `init()` installs before anything loads — and the determinism gate runs InPlace, so nothing that ran exercised the path. The one real game scene, `fps_shooter`'s, has no skinned entity.
- pinned-by: tests/snapshot_skinned_test.cpp
- lane:      unit
- proof:     `AnimatorSystem::prepareWorld()` installs the hook, and `startSimulation` calls it on the game world after the component schemas are registered and BEFORE the snapshot is loaded. `run()` keeps its lazy install as a fallback for a host that never calls `prepareWorld`, but checks `ecs_id_in_use` first; on a world where SkinnedMesh is already in use it warns that the world's palette slots will not be returned on removal — a loud leak instead of an abort. `snapshot_skinned_test` drives Snapshot Play end to end with one skinned entity: it asserts the entity really reached the play world (otherwise the hook would land on an unused component and nothing could fail), ticks three steps, and asserts the play world carries the release hook — which the fallback would not leave, so the test cannot pass for the wrong reason. Before the fix it exits 134 on the first tick. `animator_system_test` §16 pins the fallback: advancing a world whose SkinnedMesh was already in use, with no `prepareWorld`, must animate rather than abort. Mutations: dropping the `prepareWorld` call from `startSimulation` fails the hook assertion without aborting — the fallback hides the crash, which is exactly why that assertion exists; removing the `ecs_id_in_use` guard aborts §16 with the original ALREADY_IN_USE assert.
- note:      found by a test written for BUG-0061, not by looking for it. §15 of `animator_system_test` built a second world with its skinned entity already in place and only then let the animator see it — the order Snapshot Play uses — and died in flecs. The test's mistake was the runtime's.
