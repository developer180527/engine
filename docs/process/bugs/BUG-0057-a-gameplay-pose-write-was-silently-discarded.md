## BUG-0057 — a gameplay pose write to a physics body was silently discarded
- found:     2026-09-09
- status:    fixed
- class:     logic
- where:     src/plugins/jolt_plugin.h, src/runtime/runtime_sim.cpp, src/runtime/scripting/
- fixed-by:  giving the intent a NAME, not by allowing the write — see `note` below
- symptom:   setting `Transform.position` on an entity with a Dynamic `RigidBody` appeared to work and then did not: `writeBackTransforms` overwrote it from the body at the end of the step. Silent — no warning, no return value, nothing in the log. The nearest thing to a workaround was `setVelocity`, which is a different operation with different physics.
- cause:     physics owns a dynamic body's pose, and it must, because two authorities over one pose is exactly the last-writer-wins defect the command architecture exists to remove. So the write could not simply be honoured. But there was ALSO no supported way to express "put this entity there" — the operation had no name, so gameplay reached for the only thing that looked like it and got silence.
- pinned-by: tests/physics_authority_test.cpp
- lane:      unit
- proof:     `Cmd::Teleport` is now a command with a payload (`simcmd::tele`), executed by the runtime after the movement fold — after, because a teleport is a discontinuity and the tick's steering was computed for a place the entity is no longer at. It is ATOMIC across three things a Transform write could never coordinate: the backend's body pose, the ECS `Transform`, and `PrevTransform`. The last matters more than it looks — `PrevTransform` is snapshotted at the TOP of the fixed step, so without moving it the renderer would interpolate from the old pose to the new one and draw the entity SLIDING across the gap, which makes a correct teleport look like a bug. Velocity is cleared in both the rigid-body and character branches: a body that reappears across the map carrying its old momentum is the classic teleport defect. The character branch subtracts `footOffset`, because a `CharacterVirtual`'s reference point is the feet and the write-back re-adds it. Mutations: removing the velocity clear, and removing the footOffset subtraction, each fail an assertion.
- note:      SECTION 4 OF THE TEST ASSERTS THE BUG'S SYMPTOM STILL HAPPENS, deliberately. A raw `Transform` write on a dynamic body is still discarded, and that is the correct behaviour, not a residue of the bug — physics owning the pose is what makes the simulation single-authority. What stage 3a changed is that there is now a supported operation to reach for. Stage 3b's authority watcher makes the unsupported one LOUD rather than silent; this record should not be read as saying the silent drop is closed.
- open:      the teleport reaches Lua (`entity:teleport`) and the C++ `ScriptHost`, but NOT the frozen C ABI — `EngineApiPhysicsV1` is layout-frozen and gains nothing here. A native kit using the C table cannot teleport until `EngineApiPhysics2V1` is appended in stage 3b.
