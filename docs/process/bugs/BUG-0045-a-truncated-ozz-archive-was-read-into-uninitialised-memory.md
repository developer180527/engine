## BUG-0045 — a truncated ozz archive was read into uninitialised memory and used
- found:     2026-08-29
- status:    fixed
- class:     memory
- where:     src/animation/cooked_skin.h
- symptom:   a corrupt or truncated cooked mesh made `decodeCookedSkeleton` ABORT in a debug build (`Assertion failed: (size == count * sizeof(uint16_t)), archive.h:363`) and SILENTLY return a usable-looking `Skeleton` in a release build. Both on the AsyncLoader worker thread, from a file that may be a partial cook, a DDC blob from another machine, or a bad disk.
- cause:     `cooked_skin.h` guards with `ar.TestTag<T>()` and then does an unchecked `ar >> *sk`. `TestTag` validates the tag and version at the FRONT of the archive and says nothing about the body behind it. ozz's `IArchive` is explicitly documented as trusting its input — its own comment reads *"Only uses tag validation for assertions, as reading cannot fail"* — and every primitive load discards the byte count it actually got: `OZZ_IF_DEBUG(size_t size =) _archive.LoadBinary(array, count * sizeof(T)); assert(size == ...)`. `OZZ_IF_DEBUG` is empty in release, so the short read is dropped, the destination stays partially uninitialised, and ozz builds a Skeleton or Animation out of it.
- pinned-by: tests/fuzz_cooked_skin_test.cpp
- lane:      fuzz-regress
- proof:     `--seed 12660276661850738527` (generator v1) aborts against the pre-fix tree on ozz's assert and passes after. Committed to `tests/fuzz/corpus/cooked_skin/regressions.seeds`. The clang build corroborated the mechanism independently: an intermediate version of the ozz patch that dropped the read call produced `error: variable 'v' is uninitialized when used here`, which is precisely the release-build state this bug describes.
- note:      fixed in two halves, because one alone was not enough. `anim::GuardedStream` is an `ozz::io::Stream` that records every short read; both decoders check it after extraction and refuse the result rather than returning it half-built. That works in release — but NOT in debug, because ozz's assert fires *inside* `ar >> *sk`, before any post-check can run. So `third_party/patches/ozz-animation__no-asserts-on-untrusted-archive-input.patch` removes the READ-side asserts and lets the engine's guard be the authority. WRITE-side asserts are deliberately kept: we produce those bytes, so a short write is a real defect worth aborting on.
- note:      the inconsistency was the worst part. Debug aborted and release accepted, which meant the debug build could not run the fuzz lane that would have found the release bug — the library crashed first.
