## BUG-0061 — every animated entity a session spawned kept its animation buffers until Play stopped
- found:     2026-09-13
- status:    fixed
- class:     memory
- where:     src/systems/animator_system.h
- symptom:   memory that grows with the number of animated entities EVER spawned in a session rather than the number alive — for a game with a spawner, without bound until Play stops. No leak report: every byte is freed at stop, so a leak checker sees nothing, and inside a session nothing ever reads the dead entries.
- cause:     `AnimatorSystem` kept each entity's ozz state — two `SamplingJob::Context`s and five buffers sized to the skeleton — in one map keyed by entity id, cleared only by `resetWorldCache` at world teardown. The SkinnedMesh release hook returns the palette slot and nothing else. The hook's own comment argues exactly this class for the palette ("a destroyed entity leaks 8 KB, which a horde shooter does thousands of times a match"); the context sat next to it.
- pinned-by: tests/animator_system_test.cpp
- lane:      unit
- proof:     `collect()` stamps each live entity's context with the pass's epoch and, when the map holds more contexts than the pass collected — the only case in which anything can be stale — erases the unstamped ones. The steady state pays one integer store per entity and never sweeps. A sweep rather than an `on_remove` hook, because SkinnedMesh already carries the one hook flecs allows per component type, and a hook on Animator — a component kits share — would collide with any kit that sets its own. §14 spawns 16 animated entities, destroys them, and requires the context count to return to the fixture's own 1; before the fix it read 17. Mutations: disabling the sweep reads 17 again (§14); collapsing the per-world maps into one shared map fails both §15 assertions — the play world's crossfade reads 0.0167 s after six interleaved passes instead of 0.1000 (restarted every pass), and the edit world's entity with the same id shows a crossfade it never started.
- note:      the map is now kept PER WORLD, and that was forced by the fix rather than chosen. A sweep over one map shared by every world would erase each other world's contexts on every pass and restart every crossfade — and two worlds really do collide: the first skinned entity in the edit world and in a second world built the same way both had id 496 (printed by §15). The runtime drives one world per frame today (`if (!m_gameWorld)` in `tickSystems`), so the sharing was latent; the class accepts both, so it must not depend on that. `resetWorldCache` now erases only the play world's contexts, before the world is freed, so a new world landing at the same address cannot inherit them. Found while checking a premise from the 2026-09-12 audit — that the crossfade clocks are simulation state missing from the hash. They are not: nothing in the simulation reads them, and moving them onto `Animator`, as proposed, would have broken every kit, because `Animator` is in `engine_abi::componentLayoutHash`.
