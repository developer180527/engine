## 1. The question

What language are the engine's shaders written in: HLSL compiled by DXC, or
Slang? And does that choice reach WGSL for a tier H?

**Why it is expensive to get wrong.** Every shader is written in it, and the
cooker, reflection and variants are built around it. Switching later is a
rewrite of all of them.

## 2. The falsifier — written before the reads

**HLSL wins if** Slang cannot produce working tier-L output (SPIR-V for
Vulkan and Metal output) for this engine's shaders. **Slang wins if** HLSL's
route to Metal or WGSL needs a second, divergent toolchain.

**Expected:** Slang, because one source to SPIR-V, MSL and WGSL is the whole
point of "one source out"; but its non-SPIR-V targets were reported as young.

## 3. Method

Reading (rung 3): Slang's README and Khronos' announcement; Apple's Metal
Shader Converter page; Tint's SPIR-V reader documentation. **Then a spike
(rung 1, not yet run):** compile this engine's `fs_triangle.sc`/`vs_*.sc`
equivalents with each candidate to SPIR-V and Metal, and run them.

## 4. What was found

**What the sources say (rung 3):**
- **Slang** targets HLSL (D3D12), SPIR-V and GLSL (Vulkan), **MSL
  (experimental)**, **WGSL (experimental, work-in-progress)**, CUDA and CPU,
  and compiles most HLSL "with minor modifications" (README). Since
  2024-11-21 it is governed by the **Khronos Slang Initiative** (NVIDIA,
  Autodesk, Valve, Adobe, id Software and Igalia named), Apache 2.0 with LLVM
  exception.
- **HLSL via DXC** reaches SPIR-V natively. To Metal it needs a second tool:
  SPIR-V → MSL through `spirv-cross`, or **Metal Shader Converter, which takes
  DXIL, not SPIR-V** (Apple: "takes a DXIL file as input and produces a
  metallib"; needs Argument Buffers Tier 2, macOS 14 / iOS 17).
  `toolchain-shaders.md` had MSC on the SPIR-V path; that was wrong.
- **To WGSL**, HLSL has no direct route: SPIR-V → WGSL through Tint's SPIR-V
  reader, which accepts Vulkan 1.1 SPIR-V "generated by standard tooling",
  may reject features WGSL lacks, and does not describe runtime-indexed
  descriptor arrays (Dawn `docs/tint/spirv-reader-overview.md`).

**What we conclude (rung 6):**
- WGSL for tier H is a **different shader variant** either way, because tier H
  has bind groups, not bindless (study 007). So the real question is not
  "does tier L's SPIR-V convert to WGSL" (it would not, through Tint), but
  "can one source emit both a bindless tier-L variant and a bound tier-H
  variant". Slang can, from one source, if its WGSL target holds up; HLSL
  cannot, without a separate WGSL path.
- For tier L alone, both work: Slang → SPIR-V is its most mature target, and
  Slang → SPIR-V → `spirv-cross` → MSL is the fallback while its Metal target
  is experimental. HLSL needs DXC plus `spirv-cross` (or DXIL plus MSC).

## 5. Verdict — PROPOSED, not concluded

**Proposed: Slang as the source language, with SPIR-V as the canonical IR,
`spirv-cross` to MSL until Slang's Metal target is no longer experimental,
and Slang's WGSL target for tier H if tier H is built.**

It does not conclude without the rung-1 spike in §3: two of the three
targets that matter here are labelled experimental by Slang itself, and only
running this engine's shaders through them says whether that matters.
`toolchain-shaders.md` already states the language is open; it changes when
this concludes.
